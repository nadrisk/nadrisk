# Architecture
- Native uses shared Groovebox via Capacitor detection.
- The public site renders only the groovebox; About, HELP and a once-a-day welcome open as overlays inside it after a startup logo flash (welcome/Ko-fi hidden on native); native stays groovebox-only. Theme state lives in each page shell and feeds the shared Groovebox so all five palettes stay consistent. Each load boots on OLED; DISP lasts one visit.
- Use Tone.js for the browser instrument, started only after a user gesture and disposed on unmount, to provide reliable audio synthesis without hosted audio or a backend.
- Keep groovebox state and transport in a focused hook, and per-trigger voice graphs (drum, synth, sampler) in src/audio on the shared Tone raw context, so sound logic stays separate from the patch interface.
- Test new domains in origin.ts; unknown hosts stay locked against copies.

- Chords, choke assignments and A/B modulation lanes belong to each slot and are captured in sets, so recall restores performance routing without changing the original note grids.
- Master performance processing sits after the summed pads and before a safety limiter; transient capture buttons are never restored held from a saved set.
- Step-sequencer modulation is stored per slot per pattern bank (slot.mods[bank].values indexed by step) and applied only on lit steps, so the note grid stays the single place where rhythm lives.
- Master loudness and sub metering run as a silent parallel tap from the final output in that shared AudioWorklet bundle, so measurements reflect every master stage without changing audible routing.
- Step banks carry per-step vel and chance arrays beside the note grid; loop crops use stepAt() so the scheduler, recorder and grid playhead agree on which column plays.
- Double-click reset uses an explicit home or the first value seen per ResetScope+label (module map), so page switches never move it; MIDI events are ignored.
- DevicePanel owns frames; PixelScreen owns headers/controls. Drum headers temporarily replace the name with width-fitted knob values so six tabs cannot hide feedback. Phones stack; VIS stays unmounted.
- Desktop Memory uses a state-preserving Sets/Patches switch inside one frame; mobile keeps separate utilities. Panel header actions reserve measured pixel width before tabs, so Reset never overlaps pages.
- Hardware knobs (src/components/HwKnob.tsx) expose data-midi-value and accept a 'midivalue' CustomEvent, so MIDI learn drives them without synthetic pointer drags.
- Screens use integer-scaled 128x64 bitmaps and labelled hit-zones. Knob keys share the knobLayout anchor and a grid row to stay centered. Synth previews square all 16 partials with column coverage; empty additive oscillators are silent.
- Synth pitch, filter, and amplifier envelopes remain independent ADSRs, with shared draggable pixel-graph controls and backward-compatible set hydration so sound design stays direct without breaking saved sets.
- Pad holds (phrase, repeat, chord arp) are pumped from Tone's worker clock tick with a 150 ms horizon, and every voice booked ahead is tracked per pad so release, transport stop and set load cancel future notes; the grid uses a 100 ms look-ahead, so scheduling survives main-thread stalls without notes after release.
- Audio-context interruptions pause the transport in place and cancel booked notes; resume is retried on visibility return and the next tap, and the transport restarts only if the user hadn't pressed STOP, so interruptions never leave stuck or bursting notes.
- Mixer meters read a silent post-pan AnalyserNode per slot, written to the DOM per frame, so metering never re-renders the mixer.
- The master chain runs EQ → Glue → Clipper → Limiter, and the MASTER screen tabs, buttons and knobs follow that same order so display matches audio.
- Pads and live-strip keys (mutes, A–D) read raw touches with preventDefault (keys fire on lift <8px), so iOS never swallows fast taps.
- Sampler, poly and siren pad taps sustain until the last finger lifts, then release; imports accept WAV/MP3 only and are truncated to MAX_SAMPLE_SEC on decode.
- Pad pitch comes from slot.note (also the phrase root); a global Harmony (src/audio/harmony.ts) snaps NOTE knobs, walks phrases and picks chord quality in key, and sampler pitch is note relative to its sampleKey (sets v<2 migrate PTCH to NOTE), so one root drives every pitched path.
- Effects needing fresh note state use FxNode.trigger on the audio-clock path, keeping pads, phrases and sequencer hits aligned.
- hack~ transport modulation never resets active audio-buffer cursors; regression tests evaluate its actual worklet source with advancing audio time to catch sequence-boundary discontinuities.
- Gate visible loops in frameGate; defer reverb impulses and sync only changed FX. REESE contours and shared 808/ACID digits reuse the slot meter via capped PixelScreen redraws, never React audio-frame updates.
- Pad patches (src/audio/patchStore.ts) store one slot's sound fields + FX rack and load through the same hydration as set recall, so patterns, names and chokes are never touched.
- src/hooks and src/audio have scoped AGENTS.md rules; read them before edits.
- ACID uses clocked pool resets and silent pre-start cancellation to prevent note blips.
- AV uses five fixed SPACE programs and one PLASMA program warmed on context initialization (parallel compilation when supported); all shape, motion, camera, form, palette, material and FX choices are uniforms, so switching never compiles shaders. Keep integrated kick/snare/bass clocks, reference palettes and clean NAD code; reuse the bounded bus and silent analyser without audible routing or React audio-frame state. The single-row AV strip uses native world cameras and a MAT popup; global utilities live above the stage to keep phone controls clear.
- AV does not open camera hardware; cached absolute visual state restores AV OUT windows without persistent storage or extra audio routing.
- AV surface palettes use independent object/world uniforms and hydrate legacy shared colors into both; plasma uses its own palette domain, keeping surface-only patterns out of plasma. Object projections blend continuously to avoid material seams.
- AV performance is background-only via a bounded pure frame processor; publish controls on changes/hello and repeat absolute state with the existing signal heartbeat, so TV effects stay current without audio routing changes. Capture uses convex feedback and hard lifecycle gates, never idle pre-capture; clean code/grid are drawn afterwards.
- Instrument lineup is DRM, IDM, SYN, BAS ("808" kind with 808/ACID/REESE modes) and SMP; legacy poly/siren kinds convert on load in src/audio/lineup.ts, so old sets keep working without old editors.
- Instrument XY offsets (slot.xy) are applied at trigger by src/audio/xyMaps.ts and only written into knobs on COMMIT, so the centre always equals the saved patch.
- XY motion (recorded path + synced LFO) lives in slot.xy and is resolved by pure xyAt() from the transport step (src/audio/xyMotion.ts) at trigger and per grid tick for live voices, so screen and sound agree; XY screen hit-zones come from src/components/xyLayout.ts and a test forbids overlaps.
- Note length is edited by right-edge drag via src/audio/noteSpan.ts on the existing tie encoding (cells >= 2), so scheduler, sets and AV stay unchanged.
- Live performance tools (PerformanceRack) live only in the full-screen PERF overlay opened from the top bar, not in the sequencer, so the step grid keeps the full frame.
- LINK defaults to same-origin BroadcastChannel rooms; optional device rooms lazy-load the cloud transport. The mixer is the master clock (epoch + bpm, re-anchored on tempo change); decks start on its next bar via startAt and phase-lock with capped tempo trims, take mute/bank/FX commands as ctl messages, and release them if the mixer goes silent >4 s, so mixing stays seamless and no deck is left muted or filtered.
- PERF MIDI uses an explicit additional DOM root for its portal and labelled value-event controls, so saved mappings work in both shells without synthetic drag or reset gestures.
- One-device CRATE mode mounts two headless useGroovebox({ deck: true }) engines on the tab's single Tone transport (they join on bar lines, the editor's sequence is gated silent) and exposes a useLink-shaped object, so the existing mixer UI drives them and both decks are tempo-locked by construction; every engine feeds the silent tapeBus so the tape records the whole mix.
